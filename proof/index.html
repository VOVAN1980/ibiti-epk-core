EPK v2

Proof of Security

EPK gives every customer their own on-chain vault. Even if the server or AI agent holding a key is hacked, the vault itself enforces limits, allowed destinations, agent budgets, a panic button and timelocked upgrades. This page does not ask you to trust us: press the button and your browser checks every claim below directly against BSC Testnet.

What this is and is not. These are verified test scenarios on BSC Testnet with a test token (eUSD). They prove that the listed protections worked in these scenarios. They are not a guarantee that no vulnerabilities exist. EPK v2 has not yet been independently audited; nothing goes to mainnet before an audit.

Code and upgrades without moving funds

  
Each contract's bytecode hash is checked. Vault implementations must match the hash pinned in the public
  EPKRegistry. A new release can only be used after a 7-day public window, and a vault opts in through its own
  timelock (at least 2 days) — same address, same funds.

Run it yourself, without this page

  
Same checks from the command line (Python 3 only, no keys). With --build it also proves the on-chain
  bytecode equals the bytecode compiled from the open-source repository.

  
git clone https://github.com/VOVAN1980/ibiti-epk-core && cd ibiti-epk-core && git checkout feature/epk-v2
python scripts/v2/verify_evidence.py
forge build && python scripts/v2/verify_evidence.py --build
