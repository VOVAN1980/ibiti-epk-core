Protected swaps

DexGuard, ThreatFeed V2 and CompositeGuard on a separate EPKVault 2.1.0, trading through the real PancakeSwap V2 testnet router with real Chainlink price feeds. A compromised operator key and an AI agent tried to steal or waste the vault's money; every attempt was sent on-chain and rejected, while fair trades went through. Press the button and your browser checks every claim below directly against BSC Testnet.

What this is and is not. Verified test scenarios on BSC Testnet, with test funds, on a separate demo vault (the EPK v2 demo vault on the main proof page is not involved). They prove that the listed protections worked in these scenarios — not that no other attack exists; what the guards do not cover is listed in GUARDS_v2.md. EPK 2.1 is in development and not yet independently audited; nothing goes to mainnet before an audit.

Rejected attacks

  
What a compromised operator key or AI agent would try. Each attempt was really sent to the vault and failed on-chain.
  STRICT = the reason is read from the execution trace of that exact transaction.
  REPLAY = the transaction is replayed against the chain state right before its block, and no earlier
  transaction in that block touched the vault or the token (a replay is strong evidence, not a trace).
  Archived = free public nodes no longer keep that old state; the rejection itself is still checked on-chain,
  and its reason was replayed while nodes still had the state (reports archived in the repository).

A real pool 38 % below the market

  
The real WBNB/BUSD pool on BSC Testnet pays far less than the Chainlink BNB price. In step C1 a plain
  wallet with no EPK makes a 0.0001 BNB trade there and receives about 0.043 BUSD instead of about 0.070 — it loses
  roughly 38 %. In step A3 the operator key asks the guarded vault for the same trade at that pool's own
  quote; DexGuard compares it with Chainlink and the vault refuses with PriceTooLow. Fair trades on a
  pool at the Chainlink price (steps S1, S2, S6) go through. Both transactions are checked in the tables on this
  page.

Run it yourself, without this page

  
Everything on this page comes from one fixed public Git commit,
  –. A commit cannot be changed afterwards, so the claims you check here
  are exactly the claims that were published.

  
This page and the command line run the same checks: network, the document vs the evidence file, code
  hashes and the registry pin, every transaction with its events or rejection reason, and the attack window. The
  command line with --build also compiles the open-source contracts and compares them byte for byte
  with the code on chain — a browser cannot compile Solidity. A detail whose history the node no longer keeps is
  reported as archived instead of being checked, never as passed.
